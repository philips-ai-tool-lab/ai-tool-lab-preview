ENTERPRISE CHATGPT · Enterprise ChatGPT · 进阶 · 练习 04

Workspace Agent · AI Use Case Value Agent

连接内部业务背景与 AI Asset Inventory，筛选相关用例，并输出一份管理层可用的成熟度评估 HTML 报告。

约 50 分钟进阶4 internal sources + HTML

练习目标

一个能够发现、复用并评估 AI 用例的 Workspace Agent

推荐方式：ChatGPT Workspace Agent + Apps + AI Asset Inventory MCP

练习结果— 5 个有来源的候选用例— 现有可复用资产与负责人— 一份自包含的管理层 HTML 报告
ADVANCED 2

建立并连接 Workspace Agent

一个 Agent、四类内部来源、一份管理层报告。

01

打开 Workspace Agent Builder

在 ChatGPT 中进入 Agents 并选择 Create agent。这是一个用于发现和评估 AI 用例的新 Agent，不是前一个 Chief of Staff。

ChatGPT Agents ↗打开 Agent Builder
02

用一段 Prompt 创建 Agent

粘贴下方 Prompt，让 Builder 先展示 Agent 计划、来源连接和 Starter prompts。确认同时包含“发现”与“评估”，而不只是通用搜索。

WORKSPACE AGENT BUILD PROMPT
创建一个名为 AI Use Case Value Agent 的 Workspace Agent。

这个 Agent 应当：
1. 根据用户输入理解业务单元、优先事项、用户、工作流和价值目标；
2. 找出最符合当前业务背景的 AI 用例；
3. 说明每个用例为什么相关、哪些资产可以复用、已知负责人是谁，以及还缺少什么信息；
4. 为选定用例生成简洁、自包含的管理层 HTML 报告。

优先使用已连接的 Philips 内部来源，而不是开放网络。明确区分有来源的事实和假设，保留人工判断，不把评估描述成法律、监管、临床、隐私、安全或信息安全审批。

先展示建议的 Agent 计划、来源连接和 Starter prompts，再告诉我按下 Create 前需要启用哪些连接。
03

连接内部 Philips 来源

在 ChatGPT 左侧 Apps 中连接 SharePoint、Outlook Email、Outlook Calendar 和 Teams；再连接 AI Asset Inventory MCP。配置 MCP 时，复制下方 API Key。

04

为业务单元寻找候选用例

创建 Agent 后运行下方发现 Prompt。回答业务单元、优先事项、工作流和价值问题，再从有来源的候选中选一个用例。

USE CASE DISCOVERY PROMPT
帮我找出最适合当前业务单元的 AI 用例。

先询问：
- 我的业务单元或职能；
- 最重要的业务优先事项；
- 希望改进的工作流；
- 最看重的价值结果。

然后检索已连接的 Apps，返回 5 个候选用例。每个用例包括：
- 用例名称；
- 问题和预期结果；
- 目标用户与工作流；
- 与业务优先事项的匹配；
- 预期价值；
- 相关现有资产及负责人（如已知）；
- 可能的复用方式；
- 数据、集成、监管、隐私、安全或采用方面的主要依赖；
- 建议：现在评估、稍后探索或不继续。

最后请我选择一个用例进入成熟度与价值评估，并提供来源链接或来源轨迹。
05

确认选定用例的上下文

沿用候选用例的来源证据与可复用资产，只补充用户、工作流、数据、部署、风险、价值和成功指标中的关键缺口。

06

运行成熟度与价值评估

粘贴完整评估说明。Agent 应评估 8 个维度，指出最大缺口，并在证据不足时明确标记为暂定评估。

MATURITY ASSESSMENT INSTRUCTIONS
你是一名面向 healthtech 的 AI 用例成熟度评估助手。请评估一个拟议的 AI 用例，并生成适合管理层阅读的一页 HTML 报告。

先收集或确认：用例名称、问题与目标、用户与相关方、受影响的工作流、可用数据及质量、AI 方法、集成或部署背景、监管/隐私/安全/临床因素、预期价值和成功指标。信息不完整时，只询问最关键的问题；如果使用合成数据，必须清楚标记假设。

检查是否存在相似或可复用的 Agent、模型、工具、组件或工作流，并记录资产负责人和复用对可行性的影响。

按 1–5 分评估以下 8 个维度：
1. 问题清晰度与战略匹配；
2. 用户需求与工作流匹配；
3. 数据准备度；
4. 技术可行性；
5. 集成与运营准备度；
6. 临床、安全、隐私与监管准备度；
7. 治理与风险管理；
8. 价值论证与采用准备度。

每个维度给出评分、简短依据、最大缺口和下一步。最后总结总体成熟度、最强项、最弱项、阶段分类（早期探索 / 可试点 / 可规模化）和建议（现在推进 / 有条件推进 / 先补缺口）。证据不足时标记为“暂定评估”。

最终输出必须是自包含的单页 HTML：使用干净的白色背景和 Philips 风格主蓝色，不依赖外部 CDN、脚本或字体，并能够离线打开。报告应包含管理层摘要、8 个维度、优势、风险、优先建议、假设和可复用资产。
07

打开并审阅 HTML 报告

下载或打开生成的 HTML，确认离线可用；每个评分都应有依据、缺口和下一步，未支持的结论需要在分享前修正。

08

检查管理层报告

确认报告包含摘要、8 个评分维度、优势、风险、建议、假设和可复用资产，且能够在一页决策视图中快速浏览。
